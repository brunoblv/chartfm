# ChartFM Design System
# Capítulo 4 — Linguagem Visual e Direção de UI

Versão 1.0

---

# Objetivo

Este documento define a linguagem visual do ChartFM.

Não define apenas cores.

Não define apenas componentes.

Ele define a sensação que a interface deve transmitir.

Toda decisão visual deve responder:

"Isso faz o usuário querer explorar mais?"

Se a resposta for não, o elemento deve ser repensado.

---

# A personalidade do ChartFM

O ChartFM não é um sistema administrativo.

Não é um dashboard.

Não é um player de música.

Não é uma rede social tradicional.

Ele deve transmitir a sensação de uma revista musical moderna.

Imagine uma mistura entre:

Spotify

+

Letterboxd

+

Notion

+

Apple Music

+

The Verge

+

Pitchfork

Mas sem copiar nenhuma delas.

A identidade precisa ser própria.

---

# O sentimento da interface

Quando o usuário abre a Home ele deve sentir:

Elegância.

Curiosidade.

Movimento.

Descoberta.

Comunidade.

Respiração.

Nunca:

Poluição.

Pressa.

Caos.

Excesso de informação.

---

# Design Editorial

Toda Home deve parecer uma publicação editorial.

Não uma sequência infinita de cards.

Cada seção deve parecer uma matéria diferente dentro de uma revista.

---

# Ritmo Visual

A página deve possuir ritmo.

Nunca utilizar o mesmo componente repetido diversas vezes.

Exemplo ruim:

□□□□□□□□□□

□□□□□□□□□□

□□□□□□□□□□

Tudo parece igual.

A experiência fica cansativa.

---

## Ritmo recomendado

Hero grande

↓

Grid

↓

Carrossel

↓

Cards verticais

↓

Mosaico

↓

Lista

↓

Grid novamente

Cada mudança cria sensação de novidade.

---

# Hierarquia

O usuário deve entender imediatamente:

O que é importante.

O que é secundário.

O que pode esperar.

A hierarquia deve ser construída através de:

tamanho

espaço

imagem

peso tipográfico

contraste

Nunca apenas por cor.

---

# Espaço em Branco

O espaço vazio é parte da interface.

Não tentar preencher todos os espaços.

Uma Home com bastante respiro transmite qualidade.

A regra é:

Menos informação.

Mais impacto.

---

# Escaneabilidade

O usuário precisa compreender toda a Home em poucos segundos.

Mesmo sem ler.

A interface deve permitir leitura apenas pelos formatos.

Exemplo.

Hero

↓

Pessoas

↓

Reviews

↓

Charts

↓

Comunidades

↓

Feed

Cada seção deve ser reconhecida apenas pela aparência.

---

# Cards

Não utilizar um único padrão de card.

Cada tipo de conteúdo merece identidade própria.

---

## Card de Pessoa

Grande foto.

Nome.

Compatibilidade.

Badges.

Botão seguir.

Artistas em comum.

---

## Card de Review

Grande capa.

Nota.

Trecho.

Autor.

Tempo de leitura.

Comentários.

---

## Card de Álbum

Capa dominante.

Artista.

Ano.

Nota média.

Botões discretos.

---

## Card de Community

Imagem.

Nome.

Tema.

Atividade recente.

Quantidade de membros.

Botão participar.

---

## Card de Chart

Miniaturas das capas.

Autor.

Movimento da semana.

Likes.

Comentários.

---

## Card de Conversa

Muito texto.

Pouca imagem.

Participantes.

Última resposta.

Indicador de atividade.

---

# Densidade

A Home não pode parecer vazia.

Mas também não pode parecer apertada.

Cada seção deve conter aproximadamente:

4 a 8 elementos visíveis.

Nunca vinte.

Nunca apenas dois.

---

# Cores

A cor deve apoiar o conteúdo.

Nunca competir com as capas dos álbuns.

As capas já possuem muitas cores.

A interface deve ser neutra.

Paleta principal:

tons escuros

cinzas

brancos

acentos discretos

As cores vibrantes pertencem aos artistas.

Não ao layout.

---

# Bordas

Evitar excesso de bordas.

Utilizar:

sombras leves

diferença de superfície

contraste

para separar elementos.

A interface deve parecer leve.

---

# Tipografia

A tipografia precisa ser extremamente limpa.

Poucos tamanhos.

Poucos pesos.

Grande consistência.

Nunca utilizar excesso de negrito.

---

# Imagens

Imagens devem dominar a experiência.

A música é extremamente visual.

Capas.

Fotos.

Avatares.

Eventos.

Comunidades.

As imagens contam a história.

---

# Ícones

Utilizar ícones apenas para reforçar significado.

Nunca utilizar ícones apenas para decorar.

---

# Movimento

Animações discretas.

Nada exagerado.

Preferências:

Fade

Scale

Slide

Opacity

Nunca:

Bounce

Elastic

Rotações

Animações chamativas.

---

# Hover

O hover deve transmitir qualidade.

Pequenos movimentos.

Mudança de sombra.

Leve aproximação.

Transições suaves.

Nunca animações longas.

---

# Scroll

O scroll deve parecer natural.

Cada nova seção precisa parecer uma descoberta.

Não apenas mais conteúdo.

---

# Carrosséis

Utilizar apenas quando fizer sentido.

Nunca transformar toda Home em diversos sliders horizontais.

Isso prejudica descoberta.

Preferir:

Grid

Mosaicos

Cards

Carrosséis apenas para:

Pessoas

Lançamentos

Comunidades

---

# Layout Assimétrico

A Home não deve ser totalmente simétrica.

Grandes blocos misturados com blocos menores criam identidade.

Uma revista nunca possui todas as páginas iguais.

---

# Sidebar

A Sidebar deve desaparecer visualmente.

Ela não é protagonista.

Ela deve servir como navegação silenciosa.

---

# Header

O Header deve ser compacto.

Mais espaço para conteúdo.

A Home é o protagonista.

Não o menu.

---

# Sensação Premium

Toda decisão deve responder:

"Isso parece um produto premium?"

Se parecer um template pronto, deve ser descartado.

---

# Microinterações

Todos os componentes devem responder ao usuário.

Hover.

Focus.

Loading.

Empty State.

Success.

Erro.

Tudo precisa ser elegante.

---

# Skeletons

Os Skeletons devem imitar exatamente o layout final.

Nunca utilizar apenas retângulos genéricos.

Cada módulo possui Skeleton próprio.

Isso melhora percepção de velocidade.

---

# Estados Vazios

Os estados vazios devem incentivar exploração.

Nunca mostrar apenas:

"Nenhum conteúdo."

Exemplo:

Ainda não encontramos Reviews para você.

Que tal explorar novos álbuns?

Sempre oferecer um próximo passo.

---

# Sensação de Plataforma Viva

A interface deve transmitir movimento.

Novas Reviews.

Novas pessoas.

Novas Communities.

Trending.

Eventos.

Tudo muda constantemente.

O usuário deve sentir que voltar amanhã valerá a pena.

---

# Identidade Visual

O ChartFM deve ser reconhecido mesmo sem mostrar o logotipo.

A combinação de:

ritmo

cards

espaços

tipografia

hierarquia

movimento

deve criar uma identidade própria.

---

# Inspiração

Buscar inspiração em:

Apple Music (elegância)

Letterboxd (comunidade)

Spotify (descoberta)

Notion (clareza)

The Verge (editorial)

Pitchfork (conteúdo)

Mas nunca copiar componentes.

A referência deve ser conceitual.

---

# O que evitar

Não copiar interfaces de IA.

Não copiar dashboards SaaS.

Não copiar Bootstrap.

Não copiar Material Design literalmente.

Não utilizar grids extremamente rígidos.

Não repetir o mesmo card em toda página.

Não transformar a Home em uma lista infinita.

---

# Resultado Esperado

Ao abrir o ChartFM, o usuário deve sentir que entrou em um ambiente cuidadosamente curado.

A interface precisa transmitir confiança, qualidade e personalidade.

Ela deve incentivar exploração sem exigir esforço.

O usuário não deve apenas consumir conteúdo.

Ele deve sentir vontade de permanecer, descobrir novas pessoas e retornar diariamente.
